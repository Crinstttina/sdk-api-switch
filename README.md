# 让自建前端在 SDK 订阅和 API 之间随时切换

一份思路说明：一个自己写的聊天前端（带后端），怎么做到

1. **订阅（Claude Agent SDK）和 API 两个渠道随时切换**，同一个对话这一句走订阅、下一句走 API 都行；
2. **两边共用同一套工具**（自己写的内置工具 + 外接的 MCP），订阅那边怎么把工具交给模型、结果怎么回来；
3. **两边共用同一套换窗**（上下文快满时换一页新的，怎么换、怎么接上）；
4. 以及一路**踩过的坑**。

这不是一个能跑的项目，没有可安装的包，也没有测试。文中的代码是从一个真实在用的项目里提炼出来、改成通用写法的片段，用来说明思路；拿去用之前请按自己的项目改。

> **先看条款。** 用订阅账号驱动自己写的程序，能不能用、能用到什么程度，以 Anthropic 当时的官方条款和说明为准。这份文档只讲技术上怎么做，不代表任何用法是被允许的。

## 读之前

- 默认你已经有一个能用的聊天前端，接过 Messages API（流式、工具调用、思考块、提示词缓存）。
- 文中「后端」指你自己的服务器程序；「桥」指一个跑 Agent SDK 的小服务；「CLI」指 SDK 背后拉起的 Claude Code 子进程。
- 文中「渠道」指一条去模型的路：API 渠道（官方 API 或兼容的转发商）、订阅渠道（经桥走订阅额度）。

## 一句话版本

后端照常组好一份和 API 一模一样的请求（system、messages、tools）。走 API 就直接发；走订阅就交给桥。桥给每个对话养一个 CLI 进程，在进程里起一个 MCP 把后端的工具原样登记进去，模型调工具时桥把调用顺着流推回后端执行，结果再交回去。两边谁接这一句，看的是「订阅那边的会话里装的历史」和「后端这一轮组出来的历史」哈希对不对得上：对得上就接着说，对不上就从后端的库里重铸一份。所有东西都以后端的数据库为准，订阅那边的会话只是为了缓存才留着的副本。
