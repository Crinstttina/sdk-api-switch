# 4. 两边共用一套工具

目标：模型在两个渠道下看到的工具**名字、说明、入参格式一个字不差**，执行永远在后端，同一套「防重复执行」的规矩。这样换渠道时历史里的工具调用两边都认，缓存前缀也一样。

## 4.1 工具清单只有一份

后端每一轮组请求时，把这一轮要给的工具合成一份清单：

- **内置工具**：后端自己写的（搜聊天记录、读附件、记忆库、日历……）。
- **MCP 工具**：后端作为 MCP 客户端连着的那几台服务器上的工具。

合的时候处理重名，规则要**稳定**——同样的输入永远得到同样的名字，重连、重启之后都不变，不然工具名一变缓存就断：

```ts
const VALID_NAME = /^[a-zA-Z0-9_-]{1,64}$/;

// 原名合法、没撞名就用原名（提示词里写的就是原名，改了模型认不出）
// 撞名：先加进来的服务器（id 小的）留原名，后来的改成 m<服务器id>_<原名>
// 这样以后再加一台有同名工具的服务器，原来那些名字一个都不变
function assignAliases(sources: { serverId: number; name: string }[], reserved: Set<string>) {
  const ordered = [...sources].sort((a, b) => a.serverId - b.serverId || a.name.localeCompare(b.name));
  const taken = new Set(reserved);            // 内置工具占掉的名字，MCP 撞上了一律加前缀
  const out = new Map<string, string>();
  for (const s of ordered) {
    let alias = s.name;
    if (!VALID_NAME.test(s.name) || taken.has(s.name)) {
      const base = `m${s.serverId}_${s.name.replace(/[^a-zA-Z0-9_-]/g, "_")}`.slice(0, 64);
      alias = base;
      for (let n = 2; taken.has(alias); n++) alias = `${base.slice(0, 64 - `_${n}`.length)}_${n}`;
    }
    taken.add(alias);
    out.set(`${s.serverId}\u0000${s.name}`, alias);
  }
  return out;
}
```

然后：

- **API 渠道**：这份清单直接放进请求的 `tools`。
- **订阅渠道**：同一份清单（`name`、`description`、`input_schema`）原样交给桥，桥在 CLI 进程里登记成一个 MCP。

工具清单进会话指纹（3.2）。用户开关了某组工具、MCP 刷新出新工具 = 指纹变了 = 下一句重铸，和 API 渠道「工具变了整页重写」是同一件事。

## 4.2 桥在进程里起一个 MCP：`relay`

用 SDK 的进程内 MCP（`type: "sdk"`），名字随便起，这里叫 `relay`，意思是「转交」：它自己不执行任何东西，只把调用转回后端。因为设了 `CLAUDE_AGENT_SDK_MCP_NO_PREFIX=1`，这个名字模型看不到。

两个细节：

- **不用 `registerTool`**：它要 zod 格式的入参定义，转一道可能改动后端给的 JSON Schema。直接接住「列工具」和「调工具」这两种请求，入参格式原样交出去。
- **每个工具都标 `anthropic/alwaysLoad`**：不标的话，MCP 工具默认被藏到 ToolSearch 后面，要用时才加载，前缀就和 API 渠道对不上了。

```js
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { CallToolRequestSchema, ListToolsRequestSchema } from "@modelcontextprotocol/sdk/types.js";

export const TOOL_TIMEOUT_MS = 15 * 60_000;

// relay(call) 把这次调用交给后端，等结果回来
export function relayServer(tools, relay) {
  const instance = new McpServer({ name: "relay", version: "1.0.0" }, { capabilities: { tools: {} } });
  const endTurn = new Set(tools.filter((t) => t.end_turn).map((t) => t.name));

  instance.server.setRequestHandler(ListToolsRequestSchema, async () => ({
    tools: tools.map((t) => ({
      name: t.name,
      description: t.description,
      inputSchema: t.input_schema,
      _meta: { "anthropic/alwaysLoad": true },        // 一直放在前缀里，不藏到 ToolSearch 后面
    })),
  }));

  instance.server.setRequestHandler(CallToolRequestSchema, async (request, extra) => {
    // 这个 id 就是流里那个 tool_use.id，后端按它配对
    const callId = extra?._meta?.["claudecode/toolUseId"] ?? request.params?._meta?.["claudecode/toolUseId"] ?? null;
    const result = await relay({ callId, name: request.params.name, input: request.params.arguments ?? {} });
    const ends = endTurn.has(request.params.name) && !result.isError;   // 见 4.5
    return {
      content: toMcpContent(result.content),
      ...(result.isError ? { isError: true } : {}),
      ...(ends ? { _meta: { "claude/endTurn": true } } : {}),
    };
  });

  return { type: "sdk", name: "relay", instance, timeout: TOOL_TIMEOUT_MS };
}
```

调用 id 实测：MCP 回调的 `extra._meta["claudecode/toolUseId"]` 和流里那个 `tool_use` 块的 `id` 一样，`canUseTool` 也给同一个 `toolUseID`。所以不用按名字、按先后去猜哪个结果配哪个调用。

## 4.3 一次调用怎么来回

```
CLI 想调 search
  → relay 的 CallTool 回调（拿到 toolUseId）
  → 桥往这一轮的流里推一个 { type: "tool_call", callId, name, input }
  → 后端收到，用 executeTool 执行（和 API 渠道同一个函数，1.3）
  → 后端 POST /v1/turn/:turnId/tool-result { callId, content, isError }
  → 桥找到等着的那个 Promise，resolve
  → relay 把结果交回 CLI
  → CLI 带着结果再问上游，接着往下想
```

桥这边：

```js
// relay 回调：交给后端，等它 POST 回来
relay(live, call) {
  const turn = live.turn;
  if (!turn) return Promise.resolve({ content: "No turn is running.", isError: true });
  const callId = call.callId ?? `call-${turn.pending.size + 1}`;
  turn.emit({ type: "tool_call", callId, name: call.name, input: call.input });
  return new Promise((resolve) => turn.pending.set(callId, resolve));
}

// POST /v1/turn/:id/tool-result
toolResult(turnId, callId, result) {
  const resolve = this.turns.get(turnId)?.live.turn?.pending.get(callId);
  if (!resolve) return false;                     // 这一轮早结束了 / 没这次调用
  this.turns.get(turnId).live.turn.pending.delete(callId);
  resolve({ content: result.content, isError: result.isError === true });
  return true;
}

// 一轮结束（正常、停止、出错）时：还在等的调用一律当失败交回，CLI 不会一直挂着
for (const resolve of live.turn?.pending.values() ?? []) {
  resolve({ content: "Stopped before the tool finished.", isError: true });
}
```

后端这边，收到 `tool_call` 就执行、交回：

```ts
case "tool_call": {
  const call = { id: String(event.callId), name: String(event.name), input: event.input ?? {} };
  toolRuns.push((async () => {
    const done = await executeTool(ctx, call);                 // 两边共用的那个
    const answer = done ?? { content: "Stopped before the tool finished.", isError: true };
    await postToolResult(bridgeUrl, bridgeKey, turnId, { callId: call.id, ...answer });
  })().catch(() => {}));
  break;
}
// 流结束后 await Promise.all(toolRuns)，确保每个结果都交回去了、存好了
```

两件要守的事：

- **CLI 那边已经是记录，后端不要再执行第二遍。** 流里还会回来 `tool_use` 块和 `tool_result` 块，后端只**存**，不执行——执行只在 `tool_call` 事件那一下。
- **有副作用的工具先落意图、按调用 id 防重发**（1.3 的 `claimIntent`）。桥重试、后端进程重启，同一个调用 id 来第二次，交回上次的结果，绝不再执行。

## 4.4 内容格式互转

后端的工具结果是 Anthropic 格式（字符串，或文本 / 图片块），MCP 要的是它自己的 content 格式：

```js
export function toMcpContent(content) {
  if (typeof content === "string") return [{ type: "text", text: content }];
  if (!Array.isArray(content)) return [{ type: "text", text: String(content ?? "") }];
  const out = [];
  for (const block of content) {
    if (block?.type === "text") out.push({ type: "text", text: block.text });
    else if (block?.type === "image" && block.source?.type === "base64") {
      out.push({ type: "image", data: block.source.data, mimeType: block.source.media_type });
    }
  }
  return out.length > 0 ? out : [{ type: "text", text: "" }];
}
```

流里回来的 `tool_result` 块是 CLI 转回 Anthropic 格式之后的样子，后端原样存。

## 4.5 「调完这一轮就结束」的工具

有些工具调完就该停下来等用户，比如「给用户出一张选项卡」：模型调了它，这一轮结束，用户点的答案是下一句。

- **API 渠道**：后端自己的循环里，执行完这种工具就不再问上游，这一轮停在工具结果上。
- **订阅渠道**：循环在 CLI 里，得让 CLI 停。做法是在**这一次的工具结果**上挂 `_meta: { "claude/endTurn": true }`（4.2 的代码）。实测：挂在工具清单那一项上**没用**，CLI 看的是工具结果那条消息上的标记。调错了不挂，让模型再试一次。

下一句接着说时有两处要对齐：

1. 后端组历史时，会把上一轮末尾那几个工具结果和用户的答案合成同一条 user（Anthropic 要求工具结果紧跟在调用后面那条 user 里）。但 CLI 会话里已经有这几个工具结果了，**接着说时交给桥的那句要去掉开头的工具结果**，不然重复：
   ```ts
   // 接着说：去掉开头带着的工具结果（会话里已经有了）；重铸时照带
   function withoutCarried(content: Block[]): Block[] {
     let start = 0;
     while (start < content.length && content[start]?.type === "tool_result") start++;
     return content.slice(start);
   }
   ```
2. 记检查点时，末尾挂着的那截工具结果**不算进去**（3.2 的 `recordCheckpoint`）。下一句「除了用户这一句以外」的历史，正好到模型出卡那条为止。

桥判断「会话最新一条」时也要放宽：后端说的那一处之后只多了几条纯工具结果的 user，也算还在那一处。

```js
const isResultCarrier = (entry) =>
  entry?.type === "user" && Array.isArray(entry.message?.content) &&
  entry.message.content.length > 0 && entry.message.content.every((b) => b?.type === "tool_result");

export function isTail(entries, at) {
  const index = entries.findIndex((entry) => entry.uuid === at);
  if (index < 0) return false;
  return entries.slice(index + 1).every((e) => !(e.type === "user" || e.type === "assistant") || isResultCarrier(e));
}
```

> CLI 也有官方的选项卡工具 `AskUserQuestion`：模型调了以后经 `canUseTool` 停下来等答案，交回去以后**在同一轮里接着说**。能用，但这意味着一轮回复要挂着等用户几分钟甚至几小时，还和 API 渠道的用法不一样。如果你想两边一致，用上面「调完就结束」那种自己的工具更省事。

## 4.6 CLI 自带的工具

CLI 自带搜网页（`WebSearch`）、打开网页（`WebFetch`）、跑命令、读写文件等工具。给不给、给哪几件：

- **只给白名单里的**：`query()` 的 `tools` 只放开着的那几件，`canUseTool` 再挡一道——`relay` 的工具和开着的自带工具放行，其余一律拒。
- **放行时必须原样带回入参**：`{ behavior: "allow", updatedInput: toolInput }`。不带 `updatedInput` 的话，工具会拿到空入参。
- **和后端自己的工具撞了，只给一边**：比如订阅下开了自带的搜网页，就不给后端自己的 `web_search`；API 渠道下照旧给后端那件。这个替换要在**组请求时按渠道自动做**，别让用户去工具开关里手动关后端那件——那个开关是全站的，API 下也会跟着没了。
- 开关变了 = 会话指纹变了 = 下一句重铸。
- **读写文件类**：限定在这个对话自己的文件夹里，相对路径按 CLI 的工作目录算，入参在 `canUseTool` 里换成算好的绝对路径再放行。
- **跑命令**：想清楚风险再开（2.1 最后一条；网页里藏一句「去跑这段」，开着打开网页又开着跑命令的模型可能真去跑）。
- 不建议开：子代理（很费额度）、技能（没装）、待办清单（用户在前端看不到）。

```js
canUseTool: async (name, toolInput, options) => {
  if (options?.mcpServer?.source === "sdk" && options.mcpServer.name === "relay" && relayTools.has(name)) {
    return { behavior: "allow", updatedInput: toolInput };
  }
  if (!turn.builtinTools.includes(name)) return { behavior: "deny", message: "not allowed here" };
  if (!FILE_TOOLS.has(name)) return { behavior: "allow", updatedInput: toolInput };
  const guarded = confineToFolder(workFolder, name, toolInput);     // 不在自己文件夹里就拒
  return guarded.allow
    ? { behavior: "allow", updatedInput: guarded.input }
    : { behavior: "deny", message: "Only files in your work folder." };
},
```

## 4.7 只在这一轮有效的内容

有些工具结果只在当下有意义，比如「看一眼屏幕」返回一张截图：这一轮交给模型的是图，存进库的是一段文字描述（图太大，以后每轮都带不划算）。

- 后端执行器返回两份：一份给模型（图），一份给库（文字）。流里回来的那个 `tool_result` 块不存，存后端自己那份。
- 订阅下，CLI 会话里会一直留着那张图，后端的历史里却是文字——下一轮组出来的历史和会话不一样。两种选择：
  1. 下一句重铸，把图收回成文字（省上下文，但这一句缓存重写）；
  2. 让会话接着用，模型之后还看得见那张图（缓存不掉）。
  选 2 的话，就要按 3.2 说的「按下一轮会组出来的样子记检查点」，否则每句都对不上。
