# 6. 踩过的坑

都是真遇到过的。凡是写着「实测」的，都是 CLI 内部行为、不是公开接口，升级 SDK 后要重新确认（第 7 章）。

## 工具

1. **「调完就结束」的标记挂错了地方。** 挂在 `tools/list` 那一项的 `_meta` 上不管用；CLI 看的是**这一次工具结果**上的 `_meta["claude/endTurn"]`（实测）。
2. **不标 `alwaysLoad`，工具被藏起来了。** MCP 工具默认放在 ToolSearch 后面，要用时才加载，发出去的前缀和 API 渠道不一样，切渠道就整页重写。每个工具标 `_meta: { "anthropic/alwaysLoad": true }`。
3. **工具名多了前缀。** 不设 `CLAUDE_AGENT_SDK_MCP_NO_PREFIX=1`，模型看到的是 `mcp__relay__search`，和 API 渠道下的 `search` 对不上，历史里的工具调用两边不认。
4. **放行工具时没带回入参。** `canUseTool` 返回 `{ behavior: "allow" }` 不够，要 `{ behavior: "allow", updatedInput: toolInput }`。
5. **流里回来的 `tool_use` 又执行了一遍。** CLI 那边已经执行过（经 relay），流里的块只是记录。执行只在 `tool_call` 事件那一下。
6. **一轮被打断，工具调用一直挂着。** 一轮结束（停止、出错、进程退出）时，把还在等结果的调用一律当失败交回去，不然 CLI 那边挂到超时。
7. **模型把自家工具和 CLI 自带工具搞混。** 开着自带的搜网页时，一个自家的「浏览网页」工具会被模型当成搜索、改用自带的那件。工具说明里写清楚它是干什么的、和搜索有什么不同。
8. **订阅下用过工具，切到 API 第一句就 400。** CLI 一边流式吐后面的调用、一边先执行前面的，存下来的结果会比它的调用晚一条才出现。CLI 认，API 不认。给 API 回放时等重叠的调用全答完再切（4.8）；订阅那边别跟着改，不然检查点全对不上。
9. **换窗冻结的老尾巴也带着这种顺序。** 快照不能改，给 API 读出来时把晚到的结果挪回去（5.4 最后一段）。

## 会话与缓存

10. **只用后端的消息重铸，缓存只剩系统提示词。** CLI 在第一句前面塞的那几块（运行环境、模型身份、日期）后端没有。从旧会话原样抄过来（3.4）。
11. **按停止之后两边对不上。** CLI 被 `interrupt()` 以后，会话里记的是它自己的一条「用户打断了」，后端存的是半截回复。停过的会话一律不再接着用，下一句重铸。
12. **截图那一轮之后每句都重铸。** 检查点按交给桥的那份记（里面是图），下一轮从库里组出来的是文字，永远对不上。改成按「下一轮会组出来的样子」记（3.2）。
13. **会话记录被清了。** 桥报 `session_missing`；后端只要还没出过一个字，就当场改成重铸再发一次。
14. **系统提示词改了，会话里还是旧的。** 字符串系统提示词在会话第一轮就被记下来。系统提示词要进会话指纹，变了就开新会话。
15. **保温写进了模型的历史。** 往活着的会话里推占位句，那句就留在会话里了。保温、换窗的影子请求一律分叉一份不存的（`forkSession` + `persistSession: false`）。
16. **保温的选项和真聊时不一样，读不上缓存。** 工具清单、系统提示词、思考设置但凡差一点就是整页重写。真聊和保温共用同一个组请求体的函数。
17. **CLI 自己压缩了会话。** 关了还是防一手：流里见到 `compact_boundary` 就把会话标脏、下一句重铸。后端的库里没被压缩，重铸回来的还是原话。（实测挂一个多小时都没压过，所以「关掉的开关真的管用」证明不了，只能确定没出过事。）
18. **新的桥字段，旧的桥不认。** 比如 `ephemeral`：旧桥会把影子请求当成普通一句写进活着的会话。上线先桥后后端；桥对不认识的字段宁可报错也别忽略。

## 用量与额度

19. **用量重复算了。** 同一次上游调用会拆成好几条 assistant 消息，每条都带 usage。按 `message.id` 去重。
20. **输出 token 永远是 1。** assistant 消息上的 usage 是开头那一刻的；说完的数在流里的 `message_delta` 上，收尾时盖上去。
21. **「这一页多长」翻倍了。** 一轮里用了几次工具就有几次上游调用，合计的输入是每次加起来的。要显示长度取最后一次调用的输入。
22. **额度读数不更新。** 额度事件只在数值变了的时候才来，精度 1%。久了没读数就用小探针补一次（3.8）。
23. **CLI 自己偷偷起标题。** 不传 `title`，每个会话会另用小模型发一次请求起标题，白占额度。

## 模型

24. **报错被当成了模型说的话。** 订阅下用不了的模型，`result` 是 `success`，但 `is_error: true`，报错句子作为文本块出现在 assistant 里。看 `is_error`，以及 assistant 消息上的 `error` 字段。
25. **老模型名被悄悄换掉。** 有些很老的模型名不报错，但实际回话的是最新的模型。上线前逐个模型说一句，看返回里实际的 `model`，对不上的别列。
26. **CLI 列表里没有的模型其实能用。** `supportedModels()` 只报几个别名。用完整 id 逐个试，能用的补进列表。长上下文版（`[1m]`）各模型情况不一样，也要逐个试。
27. **订阅下不知道窗口多长。** 后端按「窗口的几分之一」挡附件的地方，对不知道窗口的模型按最小的算，结果一个大一点的文件就发不了。给个合理的默认值。

## 进程与网络

28. **按总时长判断超时，长回复被误杀。** 改成按「多久没收到任何事件」算，桥每 15 秒发一次心跳。
29. **冷启动慢。** 起进程到 `init` 四五秒，一个进程常驻两百多 MB。闲置关进程的时间、同时养几个，按机器内存和「愿意多等几秒」自己权衡。
30. **环境变量漏进来，改走了按量计费。** 子进程环境从零组、白名单；见到 API key 类的变量拒绝启动；`init` 里再查 `apiKeySource`（2.2）。

## 测试

31. **小模型不肯答「暗号」。** 自测里用「记住暗号 XXX-7、待会儿问你」测记忆，小模型会当成提示词注入拒答。换成一句自然的话（「我最喜欢的水果是芒果」）。
32. **自测只看「答对了没」不够。** 每一步都要看缓存的读、写数：重铸带开头几块和不带，答案一样，写入差几百 token，只有看数才看得出来。
