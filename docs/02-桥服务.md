# 2. 订阅这边：桥服务

桥是一个很小的 Node 服务：收后端交来的一轮，用 Agent SDK 的 `query()` 交给 CLI，再把 CLI 吐出来的东西翻译成事件流交回去。它不存任何业务数据，只管进程和 CLI 自己的会话记录。

## 2.1 订阅令牌：`claude setup-token`

桥要用订阅额度，就得有订阅账号的登录凭据。不要把自己电脑上 `claude` 登录后的那份凭据文件拷过去，用专门为这种场景准备的长期令牌：

1. 在一台**有浏览器**的机器上装好 Claude Code，跑：
   ```sh
   claude setup-token
   ```
   它会打开浏览器，用订阅账号登录、授权，然后在终端里打出一串令牌。**只显示这一次**，当场存进密码管理器。
2. 这串令牌**有效期一年**。在日历里记下到期日，到期前重新生成一把换上。
3. 交给桥的方式只有一种：环境变量 `CLAUDE_CODE_OAUTH_TOKEN`。桥从自己的环境读进来，**只交给 CLI 子进程**，别的地方不读、不打日志、不回传给后端。
4. 换令牌：重新跑一次 `setup-token`，把桥环境里的值换掉，重启桥。担心旧的泄露了，按官方说明把旧的授权撤掉。

关于这串令牌，实测得到的几件事：

- **它只能拿来调模型，读不了账户资料。** CLI 自己的用量接口在这种登录方式下拿不到额度（`rate_limits_available: false`），所以额度只能从流里的额度事件读（见 3.8）。
- **按官方说明的认证优先级，它排在 API key 后面。** 环境里同时有 `ANTHROPIC_API_KEY` 之类的变量，CLI 会改走按量计费，悄悄花钱。所以桥要把这类变量挡在外面（见 2.2）。
- 每个会话开头的 `system/init` 消息里，订阅登录时 `apiKeySource` 是 `"none"`。可以拿这个做第二道检查。
- 如果你打算让模型在桥那台机器上跑命令：CLI 本身**不会**把这个令牌交给模型跑的命令（实测命令里读这个环境变量是空的）。但模型和 CLI 是同一个系统用户，理论上能从进程信息里翻出来。要么别开跑命令，要么把 CLI 关进沙箱、换个用户跑。

## 2.2 子进程的环境：只放白名单

桥起 CLI 时**从零组一份环境变量**，不要从 `process.env` 继承、再挑着删。见到会改走别的计费方式的变量，**直接拒绝启动**，别悄悄删掉——悄悄删掉以后，哪天有人照着别的教程加了一个，你都不会知道。

```js
// 见到这些就不启动：它们会让 CLI 改走按量计费或者别家云
const FORBIDDEN = [
  /^ANTHROPIC_API_KEY$/,
  /^ANTHROPIC_AUTH_TOKEN$/,
  /^ANTHROPIC_BASE_URL$/,
  /^CLAUDE_CODE_USE_(BEDROCK|VERTEX|FOUNDRY)$/,
  /^AWS_/,
  /^AZURE_/,
  /^GOOGLE_APPLICATION_CREDENTIALS$/,
  /^CLAUDE_CODE_API_KEY_HELPER/,
];

const billingVars = (env) => Object.keys(env).filter((name) => FORBIDDEN.some((re) => re.test(name)));

export function readConfig(env = process.env) {
  const dirty = billingVars(env);
  if (dirty.length > 0) throw new Error(`refusing to start: ${dirty.join(", ")}`);
  const need = (name) => {
    if (!env[name]) throw new Error(`refusing to start: ${name} is not set`);
    return env[name];
  };
  return {
    bridgeKey: need("BRIDGE_KEY"),               // 后端调桥用的钥匙
    token: need("CLAUDE_CODE_OAUTH_TOKEN"),      // setup-token 生成的那串
    configDir: need("CLAUDE_CONFIG_DIR"),        // 桥专用的干净目录
    workdir: need("BRIDGE_WORKDIR"),             // CLI 的工作目录，起个中性的名字
    maxLive: Number(env.BRIDGE_MAX_LIVE ?? 3),
    idleMs: Number(env.BRIDGE_IDLE_MIN ?? 180) * 60_000,
  };
}

// 给 CLI 子进程的环境：只有这些
export function childEnv(config) {
  const env = {
    PATH: "/usr/local/bin:/usr/bin:/bin",
    HOME: config.workdir,
    LANG: "C.UTF-8",
    CLAUDE_CONFIG_DIR: config.configDir,         // 不读任何人的设置；会话记录也存在这里
    CLAUDE_CODE_OAUTH_TOKEN: config.token,
    CLAUDE_CODE_PROMPT_CACHE_TTL: "1h",          // 缓存固定 1 小时档
    CLAUDE_CODE_DISABLE_AUTO_MEMORY: "1",        // 关掉 CLI 的自动记忆（省一大截前缀）
    DISABLE_AUTOUPDATER: "1",                    // 不自己升级，版本只跟着 npm 包走
    CLAUDE_AGENT_SDK_MCP_NO_PREFIX: "1",         // 进程内 MCP 的工具名不加 mcp__relay__ 前缀
  };
  if (billingVars(env).length > 0) throw new Error("refused child env");
  return env;
}
```

几点说明：

- **`CLAUDE_CONFIG_DIR` 用一个专门的空目录。** 否则 CLI 会读到机器上别人的设置、CLAUDE.md、插件。会话记录（`projects/<工作目录>/<会话号>.jsonl`）也存在这里，它算你的用户数据，定期清。
- **工作目录起个中性的名字**（比如 `/home/chat`）。CLI 会在每个会话开头告诉模型「你在哪个目录、什么系统」，目录名叫 `my-secret-project` 的话模型就看到了。
- **`CLAUDE_AGENT_SDK_MCP_NO_PREFIX`** 实测有效：不设时模型看到的工具名是 `mcp__relay__search`，设了就是 `search`，和 API 渠道下一模一样。工具名一致，换渠道时历史里的工具调用才对得上。
- SDK 的版本**钉死**（`package.json` 里不写 `^`）。重铸要直接写 CLI 的会话记录文件，那个格式是内部的，升级前必须先跑一遍自测（第 7 章）。

## 2.3 `query()` 的选项

```js
// CLI 自己的设置走「flag 层」：等于命令行的 --settings，不读任何设置文件
const FLAG_SETTINGS = Object.freeze({
  idleCompaction: false,        // 闲着别自己压缩会话
  autoCompactEnabled: false,    // 快满了也别自己压缩（换窗由后端管，见第 5 章）
  promptCacheTtl: "1h",
  totalTokensReminder: "off",   // 别在每句、每个工具结果后面挂一行 <total_tokens>
});

export function queryOptions(turn, config, extra = {}) {
  return {
    model: turn.model,                 // 完整 id，比如 claude-opus-5-5
    systemPrompt: turn.system,         // 字符串 = 整份替换 CLI 的系统提示词，一个字不加
    cwd: config.workdir,
    env: childEnv(config),
    settingSources: [],                // 不读用户、项目、本地任何一层设置
    tools: [...turn.builtinTools],     // CLI 自带工具的白名单（见第 4 章），全关就是 []
    skills: [],
    strictMcpConfig: true,             // 只认我们传进去的 MCP
    mcpServers: {},                    // 进程内那个 relay 在 extra 里传（见第 4 章）
    settings: FLAG_SETTINGS,
    title: turn.title,                 // 传了标题，CLI 就不会另花一次请求自己起标题
    thinking: turn.thinking,           // { type: "adaptive", display: "summarized" } 之类
    ...(turn.effort ? { effort: turn.effort } : {}),
    includePartialMessages: true,      // 要流式增量
    maxTurns: turn.maxTurns,           // 和 API 渠道的工具轮数上限对齐
    ...extra,                          // canUseTool、resume、forkSession、mcpServers……
  };
}
```

要点：

- **`systemPrompt` 传字符串**，就是整份替换。CLI 会在会话第一轮把它记下来，之后一直用记下的那份。所以**系统提示词改了，必须开新会话**（会话指纹管这件事，见第 3 章）。
- **思考**：新一些的模型用 `{ type: "adaptive", display: "summarized" }`，拿得到思考摘要和签名；老一些的用 `{ type: "enabled", budgetTokens, display }`；关掉是 `{ type: "disabled" }`。选哪种，最好和 API 渠道共用同一张「模型能力表」。
- **温度没有口子**，见 1.4。
- **传 `title`**：不传的话，CLI 每个会话会另用小模型发一次请求起标题，白占额度（实测传了就没有了）。
- **`totalTokensReminder: "off"`**：不关的话，CLI 在每一句、每个工具结果后面都挂一行剩余 token 数，进历史、模型每轮都看得到。
- **CLI 还会在每个会话第一句前面自己塞几段**：运行环境（工作目录、平台）、「你是哪个模型」、「今天几号」，合起来两三百 token，只出现一次。上面这些开关都关不掉它们。活着的会话里它们不变，不碍缓存；但重铸时要原样抄回来，不然缓存会断（见 3.4）。

## 2.4 进程怎么养

- **一个对话一个 CLI 进程**，用流式输入（`prompt` 传一个异步可迭代对象）让它一直活着，用户发一句就往里推一句。
- 闲着超过一段时间就关（1 小时档缓存过期以后再留着也没用；想少等冷启动可以留久一点，比如 3 小时）。同时最多养几个，多了按最近用过的留。实测一个 CLI 进程常驻内存两百多 MB，冷启动到 `init` 四五秒。
- **关掉不等于丢**：下次用同一个会话号 `resume`，CLI 从自己的会话记录接着读，发出去的字节和活着时一样，缓存照读。养着进程只是省掉冷启动。
- 桥重启了：进程全没了，会话记录还在，下一句照样 `resume`。
- 同一个对话同时只跑一轮（后端本来就这么管着；桥这边再挡一下，忙着就报 `busy`）。

```js
// 流式输入：往一个活着的 query() 里推一条 user
function inputQueue() {
  const pending = [];
  let wake = null;
  let ended = false;
  return {
    iterable: {
      async *[Symbol.asyncIterator]() {
        for (;;) {
          if (pending.length > 0) { yield pending.shift(); continue; }
          if (ended) return;
          await new Promise((resolve) => (wake = resolve));
          wake = null;
        }
      },
    },
    push(content) {
      pending.push({ type: "user", message: { role: "user", content }, parent_tool_use_id: null });
      wake?.();
    },
    end() { ended = true; wake?.(); },
  };
}

class SessionPool {
  live = new Map(); // 对话 → 活着的进程

  open(conversation, turn, extra) {
    const input = inputQueue();
    const q = query({ prompt: input.iterable, options: queryOptions(turn, this.config, extra) });
    const live = { conversation, q, input, it: q[Symbol.asyncIterator](), fingerprint: turn.fingerprint,
                   sessionId: extra.resume ?? null, lastUuid: null, busy: false, lastUsed: Date.now() };
    this.live.set(conversation, live);
    this.trim(conversation); // 超过 maxLive 就关掉最久没用的
    return live;
  }

  sweep(now = Date.now()) {  // 每分钟跑一次
    for (const live of this.live.values()) {
      if (!live.busy && now - live.lastUsed > this.config.idleMs) this.close(live.conversation);
    }
  }
}
```

## 2.5 桥的接口

后端只调这几个，全部带桥的钥匙，走 HTTPS：

| 接口 | 做什么 |
|---|---|
| `POST /v1/turn`（流） | 跑一轮。请求里带：对话号、这一轮怎么接（第 3 章）、会话指纹、模型 / 思考 / 系统提示词 / 工具清单、新的那条 user 的内容块；重铸时再带整页历史 |
| `POST /v1/turn/:id/tool-result` | 后端执行完一个工具，把结果交回去 |
| `POST /v1/turn/:id/stop` | 用户按了停止 |
| `POST /v1/keepalive` | 保温（3.7） |
| `POST /v1/probe` | 用最便宜的模型说一句话，只为读额度（3.8） |
| `GET /v1/models` | 订阅能用的模型 |
| `GET /v1/health` | 活着没、CLI 版本、环境自检过没过 |

**心跳**：流里每 15 秒发一个空事件。冷启动 `resume` 一个很长的会话时，上游可能很久没有动静；后端这边按「多久没收到任何事件」判断断开（比如 180 秒），**不按这一轮总共跑了多久**——长回复、多轮工具本来就可能跑好几分钟。

**第二道检查**：每个会话的 `init` 事件里看 `apiKeySource`，不是 `"none"` 就当场中止这一轮，不发请求。

## 2.6 事件怎么翻译

SDK 吐出来的消息种类很多，桥只翻成后端认的这几种，每个一行 JSON：

| 事件 | 内容 |
|---|---|
| `init` | 会话号、`apiKeySource` |
| `delta` | 增量，`kind` 是 `text` 或 `thinking` |
| `block` | 一个完整的块（上游原样：思考连签名、文字、工具调用、工具结果），后端原样存 |
| `tool_call` | 模型要调后端的工具（第 4 章） |
| `usage` | 每一次上游调用各自的用量 |
| `rate` | 额度读数 |
| `retry` | CLI 在重试上游 |
| `compacted` | CLI 压缩了会话（不该发生；这个会话标脏，下一句重铸） |
| `error` | 出错了 |
| `result` | 这一轮完了：会话号、最新一条的 uuid、能不能接着用 |

```js
export function translate(message, state) {
  if (message.parent_tool_use_id) return [];           // 子代理里的不管（我们不开子代理）

  if (message.type === "system") {
    if (message.subtype === "init") return [{ type: "init", sessionId: message.session_id, apiKeySource: message.apiKeySource }];
    if (message.subtype === "compact_boundary") { state.dirty = true; return [{ type: "compacted" }]; }
    if (message.subtype === "api_retry") return [{ type: "retry", attempt: message.attempt, status: message.error_status }];
    return [];
  }

  if (message.type === "stream_event") {
    const e = message.event;
    if (e?.type === "message_start") state.streaming = e.message?.id ?? null;
    // 说完的输出数在 message_delta 上；assistant 消息上带的是开头那一刻的（输出只有 1 左右）
    if (e?.type === "message_delta" && state.streaming && e.usage) {
      state.finalUsage.set(state.streaming, { ...state.finalUsage.get(state.streaming), ...e.usage });
    }
    if (e?.type === "content_block_delta") {
      if (e.delta?.type === "text_delta") return [{ type: "delta", kind: "text", text: e.delta.text }];
      if (e.delta?.type === "thinking_delta") return [{ type: "delta", kind: "thinking", text: e.delta.thinking }];
    }
    return [];
  }

  if (message.type === "assistant") {
    // CLI 自己合成的报错（比如这个模型订阅下用不了）：字不是模型说的，不当块发
    if (message.error) { state.error = { code: message.error }; return []; }
    const id = message.message?.id;
    // 同一次上游调用会拆成好几条 assistant 消息，用量按 message.id 去重
    if (id && message.message.usage) state.usage.set(id, message.message.usage);
    state.lastUuid = message.uuid ?? state.lastUuid;
    return message.message.content.map((block) => ({ type: "block", block }));
  }

  if (message.type === "user") {
    // 只回传工具结果；用户那句是我们自己推进去的，不回传
    const content = Array.isArray(message.message?.content) ? message.message.content : [];
    return content.filter((b) => b.type === "tool_result").map((block) => ({ type: "block", block }));
  }

  if (message.type === "rate_limit_event") return [{ type: "rate", info: message.rate_limit_info }];

  if (message.type === "result") {
    const calls = [...state.usage].map(([id, usage]) => ({ id, usage: { ...usage, ...state.finalUsage.get(id) } }));
    const isError = Boolean(message.is_error) || Boolean(state.error);
    return [
      { type: "usage", calls },
      ...(isError ? [{ type: "error", code: state.error?.code ?? message.subtype }] : []),
      { type: "result", subtype: message.subtype, isError, sessionId: message.session_id, lastUuid: state.lastUuid },
    ];
  }
  return [];
}
```

注意 `result.is_error`：有些错（比如订阅下用不了的模型）`subtype` 是 `success`，但 `is_error` 是 `true`，报错的句子还会作为一个文本块出现在 assistant 消息里。只看 `subtype` 的话，你会把报错当成模型说的话存下来。

**用量按每次上游调用分开记**：一轮里用了三次工具，就是四次上游调用。后端如果要显示「这一页现在多长」，该取最后一次调用的输入，而不是四次加起来的合计。
