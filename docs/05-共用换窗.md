# 5. 两边共用一套换窗

对话聊得很长以后，每一句都要读一遍整页，又慢又贵，还可能装不下。**换窗**就是：在同一个对话里开一页新的，让模型从一个短得多的开头接着聊，界面上气泡照样连着。

CLI 自己有自动压缩，但我们在桥里把它关掉了（2.3）：压缩由 CLI 决定、内容由 CLI 写，后端的库里没有，换回 API 渠道就接不上。换窗由后端管，两个渠道走同一套流程，只是「发出去的那一下」交给不同的地方。

## 5.1 流程

整个流程在后台任务里跑（用户锁屏、切走、网页进程重启都不该打断它），每一步的结果存进一行换窗记录：

```
0. 开始：建一行换窗记录（running）；同一个对话同时只能有一行在跑（库里唯一约束）
1. 体检：最近是不是一直在报错 → 是的话不带原话，便签只记事实
2. 记忆那次（影子请求）：让模型把这一页值得长期留的存进记忆库；可以说「没有要存的」
3. 便签那次（影子请求）：让模型写一张交接便签；校验不过 = 这次没换成
4. 挑原话尾巴（开关开着时）：从这一页最后截一段原话带过去
5. 替模型调一次「读记忆」：经 MCP 调一次，超时只记原因
6. 试一下：按新一页的样子发一次，收到开头一帧就挂断
7. 一个事务里切换：新一页 active、旧页 retired、记录 succeeded
```

**除了第 2、5 步，任何一步失败 → 新一页删掉、记录写 failed 和原因，旧页一个字节没动，照常能聊。** 不需要任何回滚。后台进程崩了，接手的进程看到超过十分钟的 running 直接判失败。

第 2、5 步没成不中止：记忆没存上、记忆没读到，都只是少一点东西，便签才是硬门槛。

## 5.2 影子请求

第 2、3 步各是一次「影子请求」：

- **前缀和主对话逐字节相同**：同一个组请求的函数，同 system、同工具清单、同思考参数、同历史。只在最后接一条指令（当作用户的下一句，**不入库**、不出现在界面上）。这样整页按读缓存的价收。
- **不许为了「别调工具」去动工具清单**——动了前缀就不一样了，整页原价重写。要模型别调工具就在指令里说；调了，后端回一句「这一轮不用工具」或者丢掉重来。
- 记忆那次：只执行记忆库里「写记忆」的那几个工具，每次调用先记下来（崩了下一次换窗知道这些存过了）；别的工具一律回「这一轮只存记忆」。指令里列出这一页已经存过的，让它只补没存过的。
- 便签那次：正文先拆掉模型手写的 `<thinking>`（有些模型会自己写一段），再校验：非空、够长、几个约定的段落标记都在。
- API 渠道：缓存过期了的话，页内那一段用 5 分钟档写就够了——它只要活到第二笔影子请求用完。

**订阅渠道怎么发影子请求**：不能往活着的会话里写（那样指令会进模型的历史）。桥另起一个进程，从活着的会话「对得上的那一处」**分叉一份不存的**，跑完就关：

```js
// turn.ephemeral：换窗的影子请求、试一下
prepareEphemeral(turn) {
  const { conversation, session } = turn;
  if (session.mode === "append") {
    // 从那一处分叉、不存；活着的会话一点不动
    return this.open(conversation, turn,
      { resume: session.sessionId, ...(session.at ? { resumeSessionAt: session.at } : {}), forkSession: true, persistSession: false },
      { register: false });   // 不挂进 live，不顶掉活着的进程
  }
  // 对不上：铸一份临时的会话记录，resume 它，关的时候删掉
  const sessionId = randomUUID();
  const prelude = session.base ? preludeOf(readEntries(findTranscript(this.config, session.base) ?? "")) : [];
  writeTranscript(this.config, sessionId, synthesize({ messages: session.history, sessionId, model: turn.model, prelude }));
  const live = this.open(conversation, turn, { resume: sessionId, persistSession: false }, { register: false });
  live.tempSession = sessionId;
  return live;
}
```

后端这边，影子请求的「发出去」那一下按渠道分岔，其余全一样：

```ts
async function shadowStream(req: ChatRequest, onToolCall: ToolCallFn) {
  if (req.sdk) {
    // 订阅：交给桥，标 ephemeral；记忆那次的来回在 CLI 里跑，后端只在中间被叫去执行

```

影子请求**不存检查点**（它分叉出去的会话马上就扔了）。

> 上线顺序：**先上桥、再上后端**。旧桥不认 `ephemeral`，会把影子请求当成普通的一句写进活着的会话。

## 5.3 新一页长什么样

```
tools + system                                      ← 断点 1（不变）
（如果有固定挂在前面的设定，比如世界书）            ← 断点 2（不变）
assistant: [便签正文] [tool_use 读记忆 {}]
user:      [tool_result 读记忆的结果 / 没读到的原因]  ← 断点 3 挂在这里
（带原话时）冻结的原话尾巴：user / assistant …
新一页里的新消息 …                                  ← 断点 4（跟着最新一条走）
```

- **便签写在 assistant 那一条里**，就是「模型自己写给自己的交接」。
- **「读记忆」做成一对真的 tool_use / tool_result**：就像模型自己调过一次、拿到了这些，和它平时调的长得一样。没读到时 `is_error` + 一句原因，它需要可以自己再调。
- **tool_result 单独成一条 user**，用户新一页的第一句是另一条 user（两条 user 相连，Anthropic 照样收）。这样断点 3 能稳稳挂在 tool_result 上——要是和第一句合成一条，断点会落到第一句上，读记忆那一大段每轮都没缓存。
- 工具清单里没有「读记忆」（用户关了那组工具）也照样放这一对：历史里有工具调用、清单里没有这个工具，照样收。走 OpenAI 兼容格式的渠道不放这一对。
- 新一页组好后**显式核一遍**：每个 tool_result 都能在它前面找到对应的 tool_use，每个 tool_use 都有结果。配不上就算这次换窗失败，宁可不换也别发一个注定 400 的请求。

订阅下，这些「新一页的开头」就是后端组出来的历史的一部分，桥照常铸进会话记录，不用任何特殊处理。

## 5.4 原话尾巴

换窗时从这一页最后截一段原话带过去（比如两万 token），让新一页开头的语气接得上。截好后**冻结成快照**存进库，之后原样读出来接上，不再按消息表现算：之后用户在旧页上改字、删一句、翻版本，都只影响屏幕，模型看到的尾巴不变。

顺序是不变量：**先处理、再估长度、最后切**。按没处理的内容算切点，实际带过去的会系统性偏少。

处理（都是纯函数）：

- **思考块一律去掉**：前缀换了，新一代模型的思考块绑定前缀，回传会作废甚至 400。
- **单个工具结果超过一万多字**：留前 60% + 后 25%，中间写省略了多少字。
- **图换成 `[图片]`、文件换成 `[文件]`**。

切点：

- 从尾部往前累加到刚好超过目标，再往前、往后各找一个最近的合法切点，取实际保留量离目标近的那个。
- **合法切点 = 用户写的一句**（有字、不是后台触发的指令、不是只有工具结果的那条）。
- 切点那句前面挂着的工具结果属于没带过来的那条回复，去掉。
- 尾巴里有**别的模型写的回复**，目标减半再切一次：大段带着别的模型的原话，新模型会学旧模型的语气。

```ts
function cutAt(sizes: number[], legal: number[], target: number): number | null {
  if (legal.length === 0) return null;
  let sum = 0, i = sizes.length;
  while (i > 0 && sum < target) sum += sizes[--i];                 // 从尾部累加到刚好超过目标
  const before = [...legal].reverse().find((n) => n <= i);          // 往前最近的合法切点
  const after = legal.find((n) => n > i);                           // 往后最近的
  const kept = (n: number) => sizes.slice(n).reduce((a, b) => a + b, 0);
  const options = [before, after].filter((n): n is number => n !== undefined);
  return options.sort((a, b) => Math.abs(kept(a) - target) - Math.abs(kept(b) - target))[0];
}

function selectCarry(turns: Turn[], target: number, currentModel: string) {
  const carried = turns.map(stripForCarry);               // 1. 先处理：去思考块、压长结果、图换占位
  const sizes = carried.map(estimateTokens);              // 2. 再估长度
  const legal = carried.flatMap((t, i) => (isUserLine(t) ? [i] : []));
  let start = cutAt(sizes, legal, target);                // 3. 最后切
  if (start === null) return { ok: false, reason: "no user line to cut at" };
  if (hasOtherModel(carried.slice(start), currentModel)) start = cutAt(sizes, legal, target / 2) ?? start;
  const tail = carried.slice(start);
  tail[0] = dropLeadingToolResults(tail[0]);
  if (unpairedCalls(tail).length > 0) return { ok: false, reason: "tool calls do not pair up" };
  return { ok: true, tail };
}
```

**冻结的尾巴也会带着订阅下那种顺序。** 尾巴是换窗那一刻照「订阅那边的切法」组出来再存的，里面可能有 4.8 说的那种情况：某个调用的结果晚了一条才出现。订阅下没事；换到 API 渠道，新一页一发就 400。

快照是冻结的，不能改（改了就不是「之后原样回放」了）。做法是**读出来给 API 用的时候**，把每个晚到的工具结果挪回它的调用后面紧跟着的那条 user；挪空了、又没有别的内容的 user 去掉。订阅下照原样用：

```ts
// 只在给 API 回放时用；库里的快照一个字不改
function alignCarriedToolResults(carry: Turn[]): Turn[] {
  // 每个调用 → 它后面紧跟着的那条 user 的位置
  const answerAt = new Map<string, number>();
  carry.forEach((turn, i) => {
    if (turn.role !== "assistant" || carry[i + 1]?.role !== "user") return;
    for (const b of turn.content) if (b.type === "tool_use") answerAt.set(b.id, i + 1);
  });

  const moved = new Map<number, Block[]>();
  let changed = false;
  carry.forEach((turn, i) => {
    if (turn.role !== "user") return;
    for (const b of turn.content) {
      const target = b.type === "tool_result" ? answerAt.get(b.tool_use_id) : undefined;
      const to = target !== undefined && target < i ? target : i;   // 只往前挪
      if (to !== i) changed = true;
      moved.set(to, [...(moved.get(to) ?? []), b]);
    }
  });
  if (!changed) return carry;

  return carry.flatMap((turn, i) => {
    if (turn.role !== "user") return [turn];
    const results = (moved.get(i) ?? []).filter((b) => b.type === "tool_result");
    const rest = turn.content.filter((b) => b.type !== "tool_result");   // 用户的字、图照留
    const content = [...results, ...rest];                               // 工具结果放在最前面
    return content.length > 0 ? [{ ...turn, content }] : [];
  });
}
```

这一步只在读的时候做，库里的老快照永远不动。

## 5.5 试一下

「换成了没有」不等用户的下一句来验证，而是**换窗时当场试一下**：按新一页的样子 + 一个占位字「.」发一次，收到开头一帧就挂断（和保温同一个做法）。

- 钱几乎一样：新一页的开头本来就要写进缓存一次，试一下就是提前写，用户下一句直接读到。
- 简单得多：界面上「正在换一页」变成分隔线的那一刻，新一页就确定能用；失败只发生在换窗里，用户的话永远不会「发出去失败、再悄悄换回旧页重发」。

订阅下：新一页的历史和桥上的会话对不上，后端算出来自然是重铸；标 `ephemeral` + `untilStart`，桥铸一份临时会话记录（带上旧会话开头 CLI 塞的那几块）、收到开头一帧就挂断、删掉临时记录：

```js
// sessions.run() 里：只要开头一帧
if (turn.untilStart && value?.type === "stream_event" && value.event?.type === "message_start") {
  const message = value.event.message ?? {};
  emit({ type: "usage", calls: [{ id: message.id, usage: message.usage }] });
  emit({ type: "result", subtype: "started", isError: false, reusable: false });
  live.q.interrupt().catch(() => {});
  break;   // finally 里关进程、删临时会话记录
}
```

## 5.6 换完以后两边各自怎么接

- **API 渠道**：新一页的第一句照常组请求，前缀和「试一下」那次一样，读上它写的缓存。
- **订阅渠道**：新一页的第一句，历史和任何检查点都对不上 → 重铸（`base` 是旧会话，抄开头那几块）。铸出来的字节和「试一下」那次一样，读上它写的缓存。之后照常记检查点，接着说。
- 换窗以后切渠道也一样：两边都是从后端库里的新一页组历史，各自按第 3 章的规矩接。

## 5.7 换窗期间撞上别的事

- **模型正在回的时候**：换窗的按钮变灰。不排队，等它说完再点。
- **换窗进行中用户又发了一句**：先显示在消息流里，等换窗结束再发——换成了就在新一页里发，没换成就在旧页里发。
- **保温、定时来找用户的主动消息**：换窗记录 running 时往后推一会儿再来。换窗不算用户出声，主动消息的计时、保温的时长都不动。换成以后，「试一下」那次就是保温的新参照。
- **旧页上的操作**：「编辑并影响下文」「重新生成」不让做（它们改的是旧页的历史，模型已经看不到了）；只改屏幕的操作（仅保存、删除、复制）照常。
- **页太长、当前模型装不下**：影子请求本身就发不出去。先换一个窗口装得下的模型再换窗。
- **两台设备同时点**：库里同一个对话只能有一行 running，第二次直接回「正在换」。
